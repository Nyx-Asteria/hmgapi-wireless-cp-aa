## Readiness and negotiation contract
identityStatus() returns IdentityStatus with public final generation(long), readiness(enum), reason(String). UNAVAILABLE=no contributions or suspended; REGISTERED=contributions changed; PREPARED=validated native inputs; ARMED=native configure succeeded; ADVERTISED=historical successful matching builder with required values for that generation; FAILED=configuration failed. Neither ARMED nor ADVERTISED proves receipt, acceptance, theme eligibility or StartSession dispatch. Treat reason as diagnostics, not machine protocol.
negotiationStatus() returns public final generation(long), vehicleBuilt, themeBuilt, startRequested, startArmed, startSendCapability, startReceiveCapability (all booleans). Latest polled construction evidence, not historical aggregate or phone acceptance. Vehicle requires engine+name lookups; theme requires value lookup; startRequested is contributor opt-in, startArmed requires actual native payload and Java pending-state guards, send/receive are actual 0x4301/0x4300 list construction in successful matching builder. Both directions independent. Native observation is mutex-protected; watcher polls ~2s; lock failure skips update. Compare generation across snapshots; re-read identityStatus after negotiationStatus to reject races. Reset cached evidence on new generation, service/provider replacement or process restart. Identical registration and absent removals don't advance generation. Changed contribution, actual removal, suspend/resume do; stale reports rejected. Payload replacement/withdrawal clears StartSession fields immediately even without generation change; theme/vehicle may remain. A false flag is not proof of rejection. Do not block display activation waiting for evidence that only appears during identification. Use statuses for diagnostics and eligibility experiments, not a new global display gate.
